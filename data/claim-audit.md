# Claim audit: OAuth Runway curated guides

Audited 2026-10-19 against live official docs (re-fetched today) and the current state of `data/guides/*.json`. The question here is not whether each quote exists (the verifier already confirmed that) but whether each claim is **right**, whether the quote **supports the value for that scenario**, and what is **missing**. Paths are JSON paths inside each guide. Tier changes are computed with `src/lib/rubric.ts`.

Note: `slack.json` changed while this audit was running (22:16). `scenarios[2].factors.partnerApproval` is now `false` with a "Corrected in review" note, and this audit checks that current value.

Verdicts: Supported / Overstated / Understated / Wrong / Missing / Can't verify.

## Top corrections (ranked by impact)

1. **HubSpot `scenarios[2].scopes[6]`: remove `crm.objects.contacts.sensitive.read`.** HubSpot forbids sensitive data scopes on listed apps, so copying this scope list into a Marketplace submission gets it rejected. (H1)
2. **Gmail `scenarios[2]` and `[3]`: make the Composio redirect proxy a required step.** Google verification needs every authorized domain verified, and you can't verify backend.composio.dev. Composio documents a 302 proxy on your own domain. Without it, public verification is blocked. (M9)
3. **Slack `scenarios[2].scopes[5]`: replace `search:read` with `search:read.public` (Real-time Search API).** Also tell the `distributed` scenario that RTS is unavailable to unlisted apps. This decides how an agent can read Slack context at all. (S7, S9)
4. **Gmail `scenarios[0].factors.customerAdminApproval` → `false`** (Tier 1 → 0). Google's default allows all apps, so Trusted status is needed only if your admin restricted Gmail. (M1)
5. **Slack `scenarios[0].factors.customerAdminApproval` → `false`** (Tier 1 → 0). The restriction applies only to "some workspaces", and here that is your own admin. (S3)
6. **Gmail `scenarios[3].timeline.production.waitDays` → `[14, 42]`.** Brand and sensitive-scope review run one after the other, so 3 days is not realistic. (M6)
7. **LinkedIn `summary`: refresh tokens.** CM-approved apps are MDP partners and are expected to use refresh tokens. Only the self-serve scenario has the 60-day re-auth problem. Also add the **closed `r_member_social`** blocker to `scenarios[0]`. (L2, L7)
8. **Slack `scenarios[2].factors.demoVideoRequired` → `true`.** Slack also requires 10 weekly active users on top of the 10 active workspaces. (S6, S8)
9. **GitHub `scenarios[1].blockers`: add the org IP allow list blocker.** OAuth app tokens can't be exempted, so Composio's IPs must be allow-listed. (G8)
10. **HubSpot `mk-decide-access`: list what user-level apps lose (no webhooks, app cards or workflow actions).** (H7)
